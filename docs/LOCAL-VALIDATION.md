# 用户本地导入与验证

这份清单用于Cocos Creator 3.8.8及本机浏览器/微信工具。云端已验证共享源码，但未打开你的本地工程、未生成正式平台包。

## 先保护现有工程和存档

1. 备份或提交你本地尚未提交的修改，另存Main.scene、`.meta`和项目设置。不要用整目录覆盖把本地编辑器生成文件清掉。
2. 首次运行新版前，导出实际运行容器中的 `zhentou.save.v1` 值，保存在你自己的本地备份文件。浏览器、Cocos预览、微信小游戏各自存储隔离，分别备份。
3. 本轮仍用该键，但读v1后立即写v2；不会自动保留v1副本。要降级必须恢复备份，不能直接让旧版读取新版档。迁移测试只用备份的副本。
4. 本次候选未推送。拿到合并/提交后再在本机分支集成，不执行强制重置或覆盖未知修改。

## 导入和共享检查

锁文件中的Vite 7需要Node `^20.19.0 || >=22.12.0`，建议Node24；本轮实测24.22.1。安装后从工程根目录运行：

```sh
npm ci
npm run check
node tools/check-walk-review.mjs
npm run build:preview
npm run preview
```

浏览器访问 `http://127.0.0.1:7456`，开发调试用 `?debug=1`。按QA清单测试两高度、拖放与取消；它只能证明共享Canvas版本。

首次Cocos场景按根README的五步创建；已有场景可复用。只挂Boot，等待真实资源和类型导入后执行：

```sh
npm run typecheck:cocos
```

若提示缺 `temp/tsconfig.cocos.json`，先确认确实由3.8.8打开项目并完成导入，不要添加假cc声明。若入口重复、无画面或坐标不对，保留编辑器错误日志和场景层级，不把Canvas预览通过当作排除依据。

## 最小行为复验

- 新档仍三只，守点可自由移动；到六只后不能加第七只，继续升堡改为宽敞倍率。
- 卡片拖入、场上拖动、拖出下场；设施同样。取消、第二指、切后台不误提交。
- 不动辅助实时跟随/取消恢复；能走的玩偶搬家不瞬移，冲回来用最新守点。
- 旧12格档按非空顺序迁移前六只，超额仍在库存，资源/养成/进度保留；重启v2坐标不重排。
- 挡会迎上去，挤倒后怪继续挤墙；无人挡满1.2秒才漏，旁边玩偶吓到；首领不可挡。
- 出手动作→放出弹道→到达才掉血/跳数字；转身或下场不让在途弹道跳回身上。
- 1334/1624玩法和守点一致；安全区、微信胶囊、绵绵重叠区域都可正常操作。

## 平台构建

按 `BUILD.md` 配置本机 `COCOS_CREATOR` 与自己的 `WECHAT_APPID`。不要把账号、AppID私有配置或凭据写入提交。执行：

```sh
npm run build:h5
npm run build:wechat
npm run check:packages
```

CLI配置仍是待真实引擎确认的候选；若编辑器不接受参数，先在其构建发布面板保存配置，再按实际格式修正，不能伪造产物。

微信开发者工具打开真实 `build/wechatgame` 后，再在iPhone/中低端Android测试前后台、触屏、安全区、FPS/内存与20分钟实际波CSV。发布构建应没有debug入口，不自动上传或发布。

## 回传最少证据

版本/提交、Node和Cocos版本、失败命令与完整报错；两高度截图；拖动/取消或异常的短录屏；设备型号/系统/微信版本；真实构建日志和包校验结果。存档只在确有必要时提供脱敏测试副本，不提供账号密码或密钥。
