# 开发通用规范（三个 demo 共用）

> 给开发看。每个 demo 另有一份 `开发文档.md` 写玩法和界面细节，**两份一起读**；冲突时以 demo 自己的文档为准。
> 一起交给你的还有：`设计概要.md`（世界观和规则）、`levels.json`（关卡，已用求解器验证）、`art-manifest.json`（资源清单）、`tools/<demo>-core.mjs`（规则参考实现 + 求解器）、`common/资源对接约定.md`。

## 1 要做成什么样

- 每个 demo 是一个**独立的 Cocos Creator 工程**，能在浏览器预览里玩，也能打包成微信小游戏和 TapTap H5 在手机上玩（**两个平台都要发**，第 17 节）。
- 范围：首页 → 选关（12 关）→ 关卡 → 结算，12 关都能玩通；撤回、重来、提示、评价、存档、调试面板齐全。
- **手感要好**：这是拿来判断“这个玩法好不好玩”的 demo，动画反馈、节奏、提示是重点，不是可有可无的装饰。
- 不做：登录、广告、分享、排行榜、服务器、付费、多语言。

## 2 技术选型

| 项 | 选择 |
|---|---|
| 引擎 | **Cocos Creator 3.8.x**（用 3.8 的最新小版本），TypeScript，只用 2D |
| 设计分辨率 | **750 × 1334 竖屏**，`ResolutionPolicy.FIXED_WIDTH`（宽度铺满，高度随机型变化） |
| 平台 | 浏览器预览 + 微信小游戏 + TapTap H5（同一套代码，第 17 节） |
| 第三方库 | 运行时不引入任何第三方库；开发依赖只允许 `typescript`、`vitest`（跑纯逻辑测试） |
| Node | 18+（跑测试和 `tools/` 下的脚本） |

## 3 一次性的手工步骤（需要人在编辑器里点）

开发写代码和数据文件；下面几步需要有人打开 Cocos Creator 做一次，约 5 分钟。请在交付的 README 里写清楚。

1. Dashboard → 新建项目 → 模板选 **Empty (2D)**，项目名 `<demo>-demo`（如 `nongdan-demo`）。
2. 新建场景 `assets/scenes/Main.scene`：层级管理器里右键 → 创建 → UI 组件 → Canvas。把 `assets/scripts/Boot.ts` 拖到 Canvas 节点上。保存。
3. 项目 → 项目设置 → 项目数据：设计分辨率 750 × 1334，勾“适配屏幕宽度”，不勾“适配屏幕高度”。
4. 项目设置 → 功能裁剪：关掉 3D、物理、粒子（3D）、地形、视频、WebView、Spine、DragonBones、TiledMap；保留 2D 渲染、UI、Graphics、Tween、Audio。
5. 构建发布 → 平台选“微信小游戏”，初始场景选 `Main.scene`，设备方向“竖屏”，AppID 填自己的（没有就用测试号）。

之后所有界面都由代码生成，**不用编辑器拼界面、不做 prefab**，场景里只有一个 Canvas。

## 4 工程结构

```
<demo>-demo/
  assets/
    scenes/Main.scene                 只有 Canvas（挂 Boot）
    scripts/
      Boot.ts                         入口：屏幕适配、读 levels.json 和清单、预载资源、进首页
      core/                           纯逻辑，绝对不 import 'cc'（要能在 Node 里跑测试）
        types.ts  rules.ts  solver.ts  level.ts
      app/
        App.ts                        页面切换（首页 / 选关 / 关卡 / 结算）
        Save.ts  Stats.ts  Settings.ts
      fw/                             小框架，三个 demo 可以共用同一份
        Art.ts                        按清单加载图片，缺图时生成占位图
        Rig.ts                        rig 角色：拼部件 + 播 rig JSON 动画 + 程序动画兜底
        UI.ts                         建节点的小函数：sprite / slice / label / button / panel
        Layout.ts                     安全区、胶囊按钮避让、区域划分、棋盘自适应
        Input.ts                      滑动、点按、键盘方向键
        Tw.ts                         常用补间：弹出、按下、抖动、跳跃弧线、淡入淡出
        Toast.ts  Audio.ts  Debug.ts
      game/                           每个 demo 自己的表现层（棋盘、角色、HUD……）
    resources/
      data/levels.json                原样拷贝交付的 levels.json
      data/art-manifest.json          原样拷贝交付的清单
      art/png  art/jpg  art/parts  art/rig     美术交付的图（见资源对接约定）
      audio/                          可选
  tests/                              vitest，测 core/（不在 assets 里，Cocos 不会导入）
  package.json  tsconfig.json  README.md
```

**core 和表现层严格分开**：core 只做“给一个状态和一个操作，返回新状态和事件列表”；表现层拿事件播动画。撤回就是退回上一个状态快照，不需要“反向播放”。

## 5 界面怎么搭

- 一律用代码建节点。`fw/UI.ts` 至少提供：`sprite(parent, key, w, h)`、`slice(parent, key, w, h)`、`label(parent, text, size, color)`、`button(parent, key, w, h, onClick)`、`panel(...)`。
- 所有 sprite 都设 `sizeMode = CUSTOM`，由代码给尺寸。
- 按钮：按下缩到 0.92（0.06s），松开回弹到 1（0.12s，backOut），带一次点击音。动画进行中可以继续点（不要整屏锁死），但同一个按钮 0.2s 内不重复触发。
- 文字用系统字体（`Label`），字号不小于 24，正文 28–32。不要做位图字。（v2 起各款用自己的 OFL 字体子集，见各自开发文档。）
- **文字框**（2026-11-03 加，三款都守）：
  - 每个带底板的文字（弹窗、气泡、提示条、牌盒说明、结算的数字和次数、按钮上的字）都要有明确的**内边距**：左右 ≥ 24、上下 ≥ 16（小按钮、角标 ≥ 12）。字离底板边框不能比这更近。
  - **最小字号**：正文 24，数字和角标 22。放不下时按这个顺序处理：① 换行；② 底板变高（或变宽，按版面定）；③ 长说明分段、分页或改成“点开看全文”；④ 字号最多缩到最小字号。**不许继续缩小，不许裁掉、不许用省略号藏掉要读的内容**。
  - 会变长的数字（掌声、总分、步数、拍数、关数）按**最大可能的位数**留宽度（比如总分按 7 位、关数按 4 位），变长时版面不跳。
  - 实现上：Label 不要一律用 `Overflow.SHRINK`；正文用 `RESIZE_HEIGHT` + 固定宽度 + 换行，底板高度跟着字算；只有单行的短标签才用 `SHRINK`，并且设最小字号。Creator 3.8.8 给 Label 换 TTF 字体时会重算并改掉节点尺寸，设完字体、文字、overflow 以后要把宽高设回来（《墨团儿》踩过，见它的 NOTES 第 13 条）。
  - 测试：调试面板加“最长文案”开关，把所有文字换成该位置可能出现的最长内容（最长的提示、最大的数字），在 750×1334 和 750×1624 下截图检查；单测里扫一遍 UI 代码，不许出现没有内边距的文字底板。
- 每个页面一个根节点，切页面时淡出旧的、淡入新的（0.2s）。

## 6 屏幕适配

`fw/Layout.ts` 负责算出这几块区域（单位：设计像素，竖屏 750 宽，高度随机型在 1334–1624 之间）：

| 区域 | 位置 | 高 |
|---|---|---|
| 顶栏 | 安全区顶部往下 | 96：左边返回按钮，中间关卡名；**右侧 220 宽留空**（微信右上角胶囊按钮） |
| 信息栏 | 顶栏下面 | 64：步数 / 次数等 |
| 提示气泡 | 信息栏下面 | 0–120：有提示时出现，点掉后收起 |
| 棋盘区 | 中间剩下的部分 | 自适应 |
| 底栏 | 安全区底部往上 | 160–320：各 demo 不同 |

- 安全区用 `sys.getSafeAreaRect()`。在微信里再读 `wx.getMenuButtonBoundingClientRect()`，把胶囊按钮的底边换算成设计像素，顶栏不低于它；读不到时顶栏从安全区顶部 + 20 开始。
- 棋盘自适应：`格子边长 = floor(min((棋盘区宽 − 48) / 列数, 棋盘区高 / 行数))`，再夹在 72–128 之间；棋盘在棋盘区里居中。
- 每个 demo 的开发文档给出自己的底栏内容和棋盘区上下的留白。

## 7 资源加载（`fw/Art.ts`）

- 启动时读 `data/art-manifest.json`，按清单逐个加载：`resources.load('art/png/<key>', ImageAsset)`，再用 `SpriteFrame.createWithImage(img)` 生成 SpriteFrame。**不要依赖编辑器里图片的导入类型设置**，这样美术的图直接拷进去就能用。
- 九宫格资源（`kind: "slice"`）加载后按清单 `slice` 设置 `insetLeft/Top/Right/Bottom`，sprite 用 `Sprite.Type.SLICED`。
- 背景（`kind: "bg"`）读 `art/jpg/<key>`。
- rig 资源读 `art/rig/<key>`（JsonAsset）和 `art/parts/<key>/*`。
- 进首页前预载全部资源，显示一个简单进度条（Graphics 画）。
- **缺图就用占位图**：`Art` 提供 `node(key, w, h)`，有图返回 Sprite 节点，没图返回 Graphics 画的占位（圆角矩形 + 按类别上色 + 用 Label 写 key）。rig 资源缺部件或缺 JSON 时，退回用整图；整图也缺就用占位。这样美术没交图之前游戏也能完整地玩，图到了自动替换。
- 调试面板里列出“缺图清单”（P0 / P1 分开），方便验收美术交付。
- 清单里有、但代码没用到的 key 也在调试面板里列出来（说明清单或代码有一边漏了）。

## 8 rig 角色（`fw/Rig.ts`）

按 `资源对接约定.md`（design/通用规范/，代码仓库里在 docs/spec/）第 4 节的格式实现：

1. 根节点 = 角色在棋盘上的位置（落脚点）。整图坐标的 `anchor` 对齐到根节点原点。
2. 每个部件建一个“关节”节点放在 `pivot` 上（相对父关节；没有父亲的相对 `anchor`），部件图作为关节的子节点，偏移到 `rect` 中心。坐标换算：`x' = x − 父pivot.x`，`y' = −(y − 父pivot.y)`（y 翻转）。
3. 叠放顺序：同一个父亲下面，“自己的图”和“子关节”一起按 `parts` 数组里的先后排。
4. 动画：在 `update(dt)` 里按 `keys` 插值，写到关节的 position / angle / scale / UIOpacity / active。`rot` 是顺时针为正，Cocos 的 `angle` 是逆时针为正，**取反**。`x`/`y` 是相对关节初始位置的偏移，`y` 取反。
5. API：`play(name, { loop?, speed?, onDone? })`、`stop()`、`setPart(id, visible)`、`setFlipX(bool)`。一次性动画播完自动回 `idle`。
6. **程序动画兜底**：rig JSON 里没有某个事件、或者只有整图时，`Rig` 用内置的程序动画代替：`idle` = 根节点 sy 在 1 ↔ 0.97 之间 1.6s 呼吸；`hop` / `step` = 先压扁 0.85 再拉长 1.08；`bump` / `flinch` = 左右抖 ±6px 三下；`happy` / `cheer` = 原地跳两下 + 转 ±8°；`dizzy` = 左右摇 ±10°。
7. 眨眼：有 `blink` 部件的角色，每 2.5–5 秒随机眨一次（显示 `blink` 0.12s），idle 时才眨。

## 9 输入（`fw/Input.ts`）

- 全屏一个透明的触摸层（在棋盘层下面、按钮层上面以外的地方都能滑）。
- **滑动**：手指拖动位移达到 40 设计像素就立即触发一步（不必等抬起），方向取位移大的那个轴；触发后以当前位置为新起点，同一次拖动里每再拖 110 像素再触发一步（方便连走）。抬起时位移在 24–40 之间也算一步。
- **点按**：点在棋盘格子上，交给游戏层判断（例如点相邻格 = 往那边走）。
- **键盘**（浏览器预览用）：方向键 / WASD 移动，Z 撤回，R 重来，H 提示，空格 = 主操作（各 demo 定义）。
- 动画播放中收到的输入**缓存一个**，当前动画一结束就执行；再多的丢掉。

## 10 手感（`fw/Tw.ts`）

统一用这些预设，数值可以按手感微调，但三个 demo 风格要一致：

| 名称 | 做法 |
|---|---|
| `pop(node)` | 缩放 0.6 → 1.08 → 1，0.25s，出现时用 |
| `press(node)` | 见第 5 节按钮 |
| `shake(node)` | x 方向 ±8、±6、±4、0，共 0.3s |
| `hopTo(node, to, h)` | 0.14s 走到相邻格，中间抬高 h（默认 18），落地压扁 0.06s |
| `fadeIn / fadeOut` | 0.2s |
| `toast(text, at)` | 在某个位置上方冒一句话：淡入 0.12s → 停 0.8s → 上浮 20 并淡出 0.2s |
| `pulse(node, color)` | 描边或底色闪两下，0.4s |

- 被挡住、走不了的时候**一定要给反馈**：角色抖一下 + 目标格子闪一下 + 一句很短的提示（每个 demo 的文案见各自文档）。同一种提示 3 秒内不重复弹字，只抖和闪。
- 通关演出控制在 2.5 秒以内，期间点屏幕可以跳过直接出结算。

## 11 声音（可选，`fw/Audio.ts`）

- 美术不交音频。开发可以先用 Node 脚本合成简单的 wav 占位（正弦 / 噪声短音），放 `resources/audio/`，以后再换。
- 每个 demo 的开发文档列了要哪些音效。首页右上角下方放一个声音开关，状态存档。
- 不做背景音乐也可以；做的话音量 0.4，进出页面不断。

## 12 页面流程

```
Boot（预载）→ 首页 → 选关 → 关卡 ⇄ 结算弹窗 → 下一关 / 重玩 / 回选关
```

- **首页**：`bg_home` + `logo_title` + `btn_start` + 声音开关 `btn_sound_on` / `btn_sound_off`。点开始进选关。《纽扣剧团》没有 `btn_start`，用“开演”按钮 `btn_play` 兼做开始。
- **选关**：12 张卡片，3 列 4 行，写关卡序号和名字，显示已得评价；按顺序解锁（打过第 n 关解锁第 n+1 关），没解锁的卡片叠 `ui_lock`。调试面板里可以一键全解锁。
- **关卡**：见各 demo 开发文档。进关时显示该关 `tip`（提示气泡 `ui_tip_bubble`，九宫格），玩家点掉或开始操作后收起；顶栏旁有个小“?”可以再打开。
- **结算弹窗**：底板 `ui_panel`（九宫格）；评价三格 `ui_star_on` / `ui_star_off`；本关数据（步数 / 用时）；按钮“下一关” `btn_next`、“重玩” `btn_restart`（《纽扣剧团》用 `btn_reset`）、“选关” `btn_back`。最后一关的“下一关”换成“回首页” `btn_home`。

## 13 存档（`app/Save.ts`）

`sys.localStorage`，key = `<demo>.save`，JSON：

```json
{ "v": 1, "unlocked": 5, "levels": { "A01": { "stars": 3, "best": 5 } }, "sound": true, "tipsSeen": ["A01"] }
```

读不到或版本不对就重置。调试面板里有“清空存档”。

## 14 评价和提示

- 每关三格评价，具体条件见各 demo 文档。共同的一条：**用过提示，最多一格**。
- 提示不限次数（demo 不接广告），按一次给一步。提示的内容由 core 里的求解器从**当前状态**算出来（《纽扣剧团》用关卡里存的解），不要只会从头给。当前状态已经无解时，提示改成“退回 N 步再试”并高亮撤回按钮。
- 提示在手机上要算得快：求解超过 200ms 就改用 `levels.json` 里存的 `solution` 判断，详见各 demo 文档。

## 15 调试面板和试玩数据（这次 demo 的重点之一）

demo 是拿来判断玩法的，**所有试玩数据都要记下来**：

- 入口：首页长按标题 2 秒，或任何页面三指同时点一下。正式包也保留（demo 不上线）。
- 面板内容：
  - 一键全解锁 / 清空存档 / 跳到某关；
  - **自动演示当前关的解**（按 `solution` 一步步播，0.35s 一步），用来快速检查 12 关；
  - 强制使用占位图（对比美术）、显示帧率、显示格子坐标；
  - 缺图清单、未使用资源清单（见第 7 节）；
  - 试玩数据表 + “复制数据”按钮（微信用 `wx.setClipboardData`，浏览器用 `navigator.clipboard`）。
- 记录的事件（`app/Stats.ts`，存 localStorage，最多 1000 条，超出丢最旧的）：

| 事件 | 字段 |
|---|---|
| `level_start` | 关卡 id、时间戳 |
| `level_win` | id、用时 ms、步数、撤回次数、重来次数、提示次数、评价，以及 demo 自己的字段 |
| `level_quit` | id、用时、当时的步数、撤回、提示 |
| `hint` | id、第几次、当时是不是已经无解 |
| `blocked` | id、原因（各 demo 的被挡原因） |

- 数据表按关卡汇总：开局次数、通关次数、平均用时、平均撤回、平均提示、被挡次数最多的原因。

## 16 测试

- `core/` 必须有单元测试（vitest），至少包括：
  1. 每一关按 `levels.json` 的 `solution` 重放，最后是通关状态；
  2. 每一关用移植后的求解器从初始状态求最少步数，等于 `par`（《纽扣剧团》：求解器能找到解，且按存的解演出成功）；
  3. 各 demo 开发文档“规则测试用例”一节列出的每个用例。
- 移植时**以 `tools/<demo>-core.mjs` 为准**，行为必须一致；看不懂或觉得规则有问题，先在交付说明里提出来，不要自己改规则。
- 交付前在 iPhone 和安卓真机各玩一遍（微信开发者工具真机预览），帧率稳定在 50 以上。

## 17 打包：微信小游戏和 TapTap H5（两个平台都发）

同一套代码出两个包。平台差异集中在一个文件里（如 `fw/Platform.ts`：有没有 `wx`、能不能分享、能不能看广告、存档用哪个接口），玩法和界面代码里不写 `if (wx)`。

**统一入口与目录（2026-11-03 起三款共用）**

- `npm run build:h5`：Web 构建 + 原工程公开包后处理 + H5 ZIP，一条命令完成；`npm run build:wechat`：微信构建 + 含分包 ZIP；`npm run build:all`：按顺序完成两者，出错即停。
- H5 现支持**正常版 / 全关卡解锁试玩版**：`build:h5` 构建 Web 一次并同时生成两版，`package:h5` 用现有编译产物同时生成两版；`check:h5` 校验两份 H5。仅要 H5 时不要使用包含微信的 `build:all` / `package:all`。
- 正常 H5 仍在 `build/taptap-h5/`；全关卡版在 `build/h5-unlocked/游戏名-P阶段-H5-全关卡解锁.zip`。对应试玩命令为 `preview:h5` / `preview:h5:unlocked`，根目录启动器为 `预览H5.command` / `预览H5-全关卡解锁.command`。全关卡版开放当前阶段完整池，右上角输入关号直达循环关；不预填成绩或通关记录，两版存档命名空间与默认端口独立。全关卡版用于个人试玩，正常版保留为上传候选。
- `npm run package:all` 只整理现有编译产物，不宣称已按当前源码重新编译；单平台用 `package:h5` / `package:wechat`。`npm run check:packages` 复核两个包。
- H5 上传包固定在 `build/taptap-h5/游戏名-P阶段-H5-TapTap.zip`；微信包固定在 `build/wechat/游戏名-P阶段-微信小游戏.zip`。两边提供 `manifest.json`、`SHA256SUMS.txt`；阶段及工程适配见 `tools/release.json`。微信包保留 AppID 公共配置及全部声明分包，排除 IDE 私有配置，主包上限按 **4,000,000 字节**检查；已有更严预算继续保留。
- 工程根目录必须有可双击的 `预览H5.command`；H5 交付目录另带 `本地试玩-Mac.command` 与预览工具。也可用 `npm run preview:h5`。通过 HTTP 运行**真实上传 ZIP**，校验后解压；仅监听本机、前台运行、Ctrl+C 清理退出，不使用 `file://`。启动器需 Node.js / Python 3，不安装依赖。默认端口固定，端口冲突明确报错，不自动换源造成存档看似丢失。
- 三款具体规则见工程 `docs/BUILD.md`，共享脚本正本在 `design/tools/build-kit/`，由 `design/tools/sync-build.mjs --write` 同步；保留各款现有公开运行门禁、字体授权及屏幕/分包适配。构建与验证依全机资源预算顺序运行，不按 CPU 核数展开 worker。
- 旧包唯一副本归档到 `build/history/`；确认逐文件内容相同后才删除重复产物。源码候选包、运行包和验收证据分开保存；候选包技术检查不代替平台审核、手机测试及用户验收。

**微信小游戏**

1. 构建发布 → 微信小游戏 → 构建；用微信开发者工具打开 `build/wechatgame`。
2. **包体（2026-11-03 起改）**：用户定了以后的美术资源由用户自己上传到 OSS、远程加载，**包体大小不再作为阶段验收项**，开发不为主包腾地方、不删图、不压图。只留一条规矩，让以后切远程只改构建配置：**每个阶段新加的美术放进它自己的 Cocos Bundle**（P3 起叫 `p3`；已有的 `land2` / `meta` / `p2` 照旧），`Art.ts` 按 key 找图时依次查 `resources` 和各个 Bundle，不在玩法代码里写死 Bundle 名。远程地址、OSS 上传、合法域名这次都不做（要做时用户另说）。交付里照旧写出主包和各 Bundle 的实际字节数，只记录、不卡。
3. 开发者工具里“预览”扫码上真机。
4. 现在不需要网络请求，不需要配置合法域名（切 OSS 远程加载以后要配 `downloadFile` 合法域名，到时另说）。

**TapTap H5**

1. 用 Web 构建（web-mobile）再做发布后处理，一条命令出上传 zip（如 `npm run build:h5`）。
2. zip 结构照《墨团儿》已经上传、平台解析通过的那份：**顶层只有一个英文目录**（代号，如 `nongdan/`），目录里直接是 `index.html`、脚本和资源；不带 `__MACOSX`、`.DS_Store`、`.meta`、源码。全部资源随包，不连外网。
3. 公开包关掉调试面板入口、FPS 显示和普通日志；开发预览保持原样。
4. 竖屏：页面声明竖屏，桌面宽窗口里按 750:1334 居中显示。平台后台的横竖屏识别以 TapTap 的答复为准（《墨团儿》正在问）。
5. H5 不能用的微信能力（分享到朋友圈、开放数据域、微信激励视频）走平台层的“没有”分支：按钮不出现或换成平台自己的做法，游戏照常能玩。具体到哪个阶段做，见各款阶段计划（《纽扣剧团》P3，另两款 P5）。

**分享、排行、激励视频在两个平台上怎么做（2026-11-03 定，三款共用）**

`fw/Platform.ts` 只暴露“能力”，玩法和界面只问能力、不问平台：

| 能力 | 微信小游戏 | TapTap H5（这一轮） |
|---|---|---|
| `shareChat`：发给好友 / 群 | `wx.shareAppMessage`（图用离屏合成的战绩图） | 没有：分享弹窗里不出“分享给好友”按钮 |
| `shareTimeline`：右上角菜单发朋友圈 | `wx.showShareMenu` + `wx.onShareTimeline`（有这个 API 才开） | 没有 |
| `saveImage`：保存战绩图 | `wx.saveImageToPhotosAlbum`（要相册授权；被拒就提示“可以截屏保存”） | 把战绩图整张铺在一个浮层上，下面一行“长按图片保存，或者截屏”；再给一个“下载图片”按钮（`<a download>`，浏览器不支持就不显示） |
| `friendRank`：好友排行 | 开放数据域（`wx.setUserCloudStorage` / `wx.getFriendCloudStorage`） | 没有：排行页只显示“我的纪录”（几项本地纪录 + 一句“好友排行在微信版里”） |
| `rewardedAd`：激励视频 | `wx.createRewardedVideoAd`，广告位 id 空 = 没开通 | 没有：所有“看视频换 X”的地方直接给（按钮写“这次免费”，不挂视频小图标） |

- 战绩图在两个平台上用同一个离屏合成函数画，只有“拿到图以后做什么”不一样。
- **分享从不给奖励**，两边一样。
- TapTap 自己也有排行榜、分享和广告的 SDK（要在 TapTap 开发者后台建排行榜、开广告位，用户登录 TapTap）。**这一轮不接**；以后用户决定接时，只在 `Platform.ts` 里给 H5 补上对应能力，界面不用改。
- 调试面板加“平台能力”开关，五项能力可以逐个关掉，在浏览器里就能看到“没有”分支的样子。

## 19 编码约定

- TypeScript `strict: true`，不用 `any`（微信 API 的类型可以用一个 `declare const wx: any` 例外）。
- 文件、类、函数名用英文；注释可以写中文，写“为什么”，不写“做了什么”。
- 数值（时长、间距、颜色）集中放在每个 demo 的 `game/Theme.ts`，不要散在各处。
- 不在 `update()` 里分配新对象；对象多的特效（粒子、彩纸）用对象池。
