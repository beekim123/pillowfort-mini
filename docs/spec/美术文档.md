# 《枕头堡》美术文档（P1）

> 给美术（argon）和开发看。**美术做法照 `美术技术方案.md`：美术交代码，不交图**——每个资源一个 Canvas2D 出图模块，游戏加载时在手机上按实际像素画出来。本文定这一版具体画什么、每个资源怎么跑、分几批交。
> 世界和角色见 `设计概要.md`；清单的正本是 `art-manifest.json`（key、尺寸、级别、动作以它为准）。
> **布局和交互由我们定，美术只画东西**：每件东西放在屏幕哪里、多大，照 `art-manifest.json` 的 `pos` / `display` 和 `levels.json` 的 `nest`（月牙枕头窝，色块示意 `布局方案/站位设计.png`）；预览页的整屏也照这些坐标摆，不要自己排。
> 本文只写 P1（前 3 个梦）。P1 分 **4 批**交，**先交第 1 批看效果**，满意了再发下一批。

## 0 和 `美术技术方案.md` 的关系

做法（交代码、手机上出图、四种运行级别、硬规则、预算、预览页）**全部照它**。只有一处改了：**哪些资源用哪一级**。那份方案是按画风库的实测写的，没有从头参与这款的设计；对着这款的战斗画面重新排了一遍：

| 资源 | 方案原来 | 现在 | 为什么 |
|---|---|---|---|
| 绵绵（领头羊） | L0 实时 | **L1 部件 + rig** | 一直在屏幕上、只有约 110 像素高；实时重画的好处在这个尺寸上看不太出来，却要一直占手机的力气 |
| 糯糯（睡觉的小孩） | L0 实时 | **L1 部件 + rig** | 盖着被子睡觉，几乎不动（呼吸、翻身）；L1 足够 |
| 大噩梦 | L0 | **L0（战斗里唯一实时的）** | 一次只有一只、个子大（约 300 像素）、是这一区的高潮，值得实时画 |
| 展示场景（早安卡、纸箱开出、解锁卡上的大图） | L0 | **L1 模块的“实时模式”** | 同一个 L1 模块放大到 2–3 倍，部件按沸腾节奏现画（见 2.2），**不用另写代码** |
| 枕头堡、栅栏 | （没写） | **bg** | 大块静态的东西，进梦时画一次；枕头堡按等级换样子再画 |
| 界面 | 九宫格或生成 | **bg 级的 UI 模块**（第 4 批） | P1 先用开发的简单占位，最后一批再画 |

结果：**战斗里同时实时画的最多 1 个**（打大噩梦时），比方案的 3 个省一大截，低端机更稳。

## 1 画风：水粉颗粒（夜色）· 梦里

底子是画风库的 `grainy-gouache`（`styles/grainy-gouache/`：README、`style.config.mjs`、`gouache.mjs` 笔法、`out/` 三件试画）。**笔法照它，交付改成 Canvas2D 代码**。

一句话：**夜里的梦，柔和的水粉色块 + 往边缘和暗处聚的细颗粒，没有描边；玩偶是暖的、亮的、毛茸茸的，噩梦是深色的、软的、只露一双发亮的眼睛，羊是白的。**

### 1.1 要遵守的画法（照原画风）

- **不描边**：形体之间靠明暗差和颗粒边分开。
- 每个大形体一个径向渐变，4 档（受光 → 中间 → 暗 → 边缘），**光从左上来**（光点约 0.42, 0.30）。
- 颗粒：夜空靛蓝，往形体边缘和暗处聚；脸上的细节（嘴、高光）画在颗粒外面保持干净。**颗粒用画笔库预先生成的颗粒纹理铺**（`clip` + `drawImage`），不要一颗颗画（方案 3.3 第 4 条）。
- 背光侧一道柔和的月光（`rim`），把角色从深色底上托出来。
- 眼睛（玩偶）：奶油色圈 + 大黑瞳 + 一颗四角星高光 + 一个小圆点。
- 脚下一块柔和的深色椭圆影（`pool`）。

### 1.2 这一款要改的

- **噩梦的眼睛是另一种**：没有奶油圈，是一对**发光的眼睛**（暖白 / 淡黄，外面一圈柔光），瞳孔是竖的小黑点或一道缝；圆滚滚、有点委屈、**吓人但不恐怖**（没有牙、没有血、没有尖爪）。
- **噩梦是深色的，梦的背景也偏暗**——这是最大的风险。规矩：背景是**中间调、偏灰、低饱和**；噩梦比背景**更暗**，靠**淡紫色的月光边 + 发光的眼睛**认出来；玩偶和羊比背景**亮**、暖。**转灰度检查：玩偶 / 羊最亮，背景中间，噩梦最暗**，三层分得开。
- 玩偶是**旧的毛绒玩具**：毛有点起球、缝线若隐若现、颜色温暖但不艳。**不要泰迪熊**（竞品的主角就是泰迪熊）；不要纽扣眼（《纽扣剧团》用过）。
- 原画风里的“杂音斑”这里不用。

### 1.3 色板（起点，美术可以调，调了写进交付说明）

`palette.json` 从 `grainy-gouache/style.config.mjs` 起步（`grain`、`rim`、`cream`、`blush`、`faceInk`、`pool`、各色族 ramp 照用），再加：

| 色族 | 用在 | 建议 |
|---|---|---|
| `night` | 梦的背景（中间调，偏灰） | `#3A3F6B` → `#2B2F55` → `#1F2242` → `#171A33` |
| `fog` | 梦的上边（噩梦从这里出来的那片雾） | `#2A2448` → `#1A1630` |
| `nightmare` | 噩梦的身体（比背景暗） | `#2A2850` → `#1C1A3A` → `#120F26` → `#0C0A1C` |
| `nmRim` | 噩梦的月光边 | `#B9A8FF`（半透明） |
| `nmEye` | 噩梦发光的眼睛 | `#FFF3C4` 中心、`#FFD86B` 外圈 |

| 五种属性 | 打中特效、状态 | 枕头 `#FFF1D6`、暖 `#FF9A45` / `#FFD35E`、凉 `#8FE3FF`、静电 `#FFF27A` + `#C9A8FF`、臭 `#A6C35A` |

玩偶的身体用原有的 `moss`（呼呼）、`gold`、`orange`、`coral`、`teal`、`berry`、`violet` 等 ramp。

### 1.4 要的样子：活的（2026-11-06 加）

用户看了第 1 批，想要的样子最接近**你上次在画风库做的实时版**（`style-lab/index.html` → 官方做法 → 墨线手绘那 4 个；返修包的 `参考/` 里有拷贝和说明，质感参考是同目录的水粉颗粒试画）：**笔触多、边在沸腾、动起来很生动**——只是画法换成本节的水粉颗粒。具体：

- **形体是一笔笔叠出来的，不是一个渐变填满的光滑矢量形**：大形体先铺一层底色，再沿形体走向叠几十道半透明的水粉短笔（有干笔的飞白、边不齐），暗处多叠、受光处少叠；轮廓边是笔触的边，不是一条光滑的曲线。
- **颗粒在 1× 下肉眼看得见**，往边缘和暗处聚（1.1 节）。
- **沸腾要看得出来**：3 张变体之间，笔触的位置、轮廓边的起伏、颗粒都在变（造型不变），轮换起来像手绘动画那样“活”着，不是只有颗粒在闪。
- **预算是让你用的**：L1 每个部件、L2 每帧上限 3000 次画图调用；常见在几百到一千多次。第 1 批每个部件 26 次左右，说明笔触远远不够。
- **动作有手绘动画的弹性**：预备、挤压拉伸、跟随（耳朵、尾巴、丝带晚一点到），`idle` 里也要有小的次要动作，不只是整体上下浮。
- 造型照第 3 节的描述从这个世界里长出来，不套常见模板（例如一圈波浪下摆的“床单鬼 / 吃豆人幽灵”；恐龙看起来像乌龟）。

## 2 怎么跑：级别和模块（细化方案第 2、3 节）

### 2.1 每个模块的样子

所有模块：ES module、只用 Canvas2D、坐标写**设计像素**（屏幕宽 750）、确定性（同一个 `seed` + `boil` 永远同一张图）。生成器传 `opt = { seed, boil, scale, variant }`，模块自己 `ctx.scale(opt.scale, opt.scale)`。

```js
// L1 部件 + rig（玩偶、绵绵、糯糯、设施、手电筒）
export default {
  key: 'toy_huhu', level: 'L1', size: [140, 150], anchor: [70, 138], boil: 3,
  parts: [                     // 按绘制顺序（从后往前），坐标都是整张画布的设计像素
    { id: 'shadow', parent: null, rect: [30, 128, 80, 18], pivot: [70, 138] },
    { id: 'body',   parent: null, rect: [28, 50, 86, 92],  pivot: [70, 138] },
    { id: 'blink',  parent: 'head', rect: [...], pivot: [...], hidden: true },
    // 不需要沸腾的小部件写 boil: false（只画一张）
  ],
  drawPart(ctx, id, opt) { /* 用整张画布的坐标画这一个部件；生成器负责裁到 rect */ },
  anims: { idle: { dur: 1800, loop: true, tracks: [/* 照 资源对接约定 4.2，可以烘焙成密集 linear 关键帧 */] },
           attack: { dur: 500, tracks: [...] }, skill: {...}, cheer: {...} },
};

// L2 帧动画（噩梦、羊）
export default {
  key: 'nm_eyes', level: 'L2', size: [120, 120], anchor: [60, 108], boil: 1,
  variants: ['normal', 'elite'],               // 精英：生成器另画一套，尺寸 ×1.4
  anims: { walk: { frames: 8, fps: 10, loop: true }, hit: { frames: 4, fps: 12 }, burst: { frames: 8, fps: 14 } },
  drawFrame(ctx, anim, i, opt) { /* opt.variant = 'normal' | 'elite' */ },
};

// L3 笔刷 + 特效配方（打中、属性效果、光束）
export default {
  key: 'fx_warm', level: 'L3',
  brushes: { puff: { size: [48, 48], draw(ctx, opt) {} }, spark: { size: [16, 16], draw(ctx, opt) {} } },
  effects: {
    hit:  { brush: ['puff', 'spark'], count: [6, 10], life: [0.25, 0.45], speed: [60, 180], angle: [0, 360],
            scale: [0.6, 1, 0.2], alpha: [1, 0], tint: ['#FFD35E', '#FF9A45'], blend: 'add' },
    burn: { attach: 'target', loop: true, brush: ['puff'], rate: 8, life: [0.4, 0.7], speed: [10, 30], angle: [250, 290],
            scale: [0.4, 0.7, 0.1], alpha: [0.8, 0], tint: ['#FF9A45'] },
  },
};

// bg（背景、枕头堡、栅栏，以后的界面件）
export default { key: 'bg_dream_0', level: 'bg', size: [750, 1624], draw(ctx, opt) {} };

// L0 实时（大噩梦，第 3 批才有）
export default { key: 'boss_closet', level: 'L0', size: [300, 300], anchor: [150, 280],
  init(opt) { return state; }, update(state, dt, events) {}, draw(ctx, state, opt) {} };
```

- **特效配方的字段**（开发照这个写一个简单的精灵粒子：对象池、合批）：`brush` 随机选一个；`count`（一次喷几个）或 `rate`（每秒几个，`loop` 时）；`life` 秒；`speed` 设计像素 / 秒；`angle` 度（0 = 右、90 = 下）；`scale` = [出生, 中间, 结束]；`alpha` = [出生, 结束]；`tint` 随机一个颜色乘上去；`blend` = `normal` / `add`；`attach: 'target'` 跟着目标走；可选 `gravity`（设计像素 / 秒²）、`spin`（度 / 秒）。不够用的写进交付说明，我们来加。
- **`boil`**：每个部件 / 每帧画几张颗粒沸腾变体（`opt.boil` = 0、1、2）。L1 在游戏里每秒轮换 6–8 次，相邻部件错开相位。L2 噩梦同屏很多，`boil: 1` 就够（帧动画本身在动）。**`opt.boil` 可以是任意整数**（实时模式会一直往上数），模块用它混进随机数，不要只认 0–2。
- 动作名照第 3 节。非循环动作播完要回到 `idle` 第一帧的姿势。

### 2.2 L1 的“实时模式”（展示场景用，美术不用另写）

早安卡、纸箱开出新玩偶、解锁卡上要一只大大的玩偶：生成器用同一个 L1 模块，按 2–3 倍放大，**每秒 6–8 次用新的 `boil` 现画部件**，部件照常跟 rig 动。所以 L1 模块放大到 3 倍也要好看（线宽、颗粒按设计像素定，方案 3.3 第 3 条）。

## 3 P1 资源

尺寸是**设计像素**的画布（游戏里按手机实际像素再乘 `scale`）。`anchor` 是脚底中心。`display` 是屏幕上大约多大（画布会按它缩放）；`pos` 是 anchor 落在 750×1334 屏幕上的哪一点（我们定的布局，见 `levels.json` 的 `nest`）。

**视角**：俯视 3/4（看得到头顶和正面）。噩梦从屏幕上方的雾里往下、往窝里聚；玩偶站在窝里的小圆垫上，**脸朝镜头**，出手时身子朝上方（梦里）一倾。

|---|---|---|
| 全部 | 9 只 | `startled`（0.5 s）：噩梦从身边挤过去时吓一跳 |
| **挡** | 方方、软软 | `block`（0.8 s 循环）：身体前倾、脚下蹬住，一下一下往前顶（噩梦那边同时播 `push`）；`knocked`（0.4 s）：被挤倒，**停在趴着的姿势**（这一个不回 `idle`）；`down`（1.6 s 循环）：趴着喘气、晕乎乎；`getup`（0.7 s）：爬起来、拍拍身上，回到 `idle` 第一帧 |
| **冲** | 阿冰 | `dash`（0.4 s 循环）：肚皮着地往前滑（头朝上方、背对镜头一点）；`strike`（0.25 s）：撞一下（连撞 3 次）；`back`（0.5 s 循环）：摇摇摆摆跑回来（朝镜头） |
| 打、帮 | 其余 | 没有多的 |

### 3.7 背景怎么画（三张都照这个）

- **750×1624，底对齐**：矮的手机（1334 高）会把**顶上 290** 裁掉，重要的东西别放在那里。
- 从上到下（括号里是 1334 高屏幕的坐标，画布坐标再加 290）：顶上一片**雾**，到屏幕 y≈262 渐淡（噩梦从雾的下沿出来，`fog` 色）→ 中间是**梦的地面**（y 262–774，噩梦往窝里走的地方，**平、静、中间调**，不要有抢眼的东西）→ 底下 560 高（y 774 起）是月牙窝 `obj_fort` 盖着，背景这里画床单 / 地毯就行。
