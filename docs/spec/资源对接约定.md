# 资源对接约定（美术 ↔ 开发）

三个 demo 共用这份约定。美术按它交图，开发按它读图；**双方都只认 `<demo>/art-manifest.json` 里的 key**，名字、尺寸、部件以清单为准。清单要改（加资源、改尺寸、改部件名），先改清单，再各自改。

## 1 单位和坐标

- **1 格 = 128px。** 所有资源都按“格子边长 128px”来画。游戏里格子实际显示 88–128 设计像素，引擎统一按 `格子边长 / 128` 缩放。
- 资源里的坐标一律是**像素、原点在左上、y 朝下**（和 SVG 一样）。开发换算到 Cocos（y 朝上）时自己翻转。
- `size`：PNG 的像素尺寸，等于 SVG 的 `viewBox`。画布大小固定，不要按内容裁边。
- `anchor`：贴到格子“落脚点”上的那个点。地块类（`tile_` / `cell_` / `ink_`）默认是正中心；站着的东西（角色、物件、道具）是**底部接触地面那一点的中心**。落脚点在格子里的位置由各 demo 的开发文档规定。
- `slice`：九宫格边距 `[左, 上, 右, 下]`。四个角放装饰，四条边的中段和中心要均匀（会被拉伸）。

## 2 文件命名和目录

key 用小写英文和下划线，前缀表示类别：

| 前缀 | 类别 | 前缀 | 类别 |
|---|---|---|---|
| `hero_` | 主角 | `tile_` / `cell_` | 地块、格子状态 |
| `puppet_` / `owner_` / `reveal_` | 其他角色、插画角色 | `ink_` | 墨层（《墨团儿》） |
| `obj_` / `prop_` | 物件、道具 | `fx_` | 特效贴图 |
| `ui_` / `btn_` | 界面件、按钮 | `bg_` / `stage_` | 背景、舞台框 |
| `goal_` / `leaf_` / `pip_` | 各 demo 特有 | `logo_` | 标题字 |

美术交付到 `<代号>/art/`（收回后整理进 `design/style-lab/practice/<id>/art/`，再拷进代码仓库的 `assets/resources/art/`）：

```
art/
  png/<key>.png                 每个 sprite / slice / rig 资源的整图（静止的样子）
  jpg/<key>.jpg                 背景（kind = bg）
  parts/<key>/<部件 id>.png      rig 资源的每个部件，单独一张
  rig/<key>.json                rig 资源的部件位置和动画（格式见第 4 节）
  svg/<key>.svg                 源文件（动画版，能在画风库里悬停看动画）
  mock/game.png                 一张 750×1334 的整屏效果图（见美术通用规范）
  scripts/                      出图脚本，能一条命令重新出全部图
  manifest.json                 交付时的清单副本：在 art-manifest.json 的基础上给每项加 "done": true / false
  notes.md                      加了哪些颜色、做了哪些取舍、有什么要确认（照 style-lab out/notes.md 的写法）
```

开发把 `png/ jpg/ parts/ rig/` 原样拷进 Cocos 工程的 `assets/resources/art/`，按下面的路径读（不带扩展名）：

| 资源 | 读取路径 |
|---|---|
| 整图 | `art/png/<key>` |
| 背景 | `art/jpg/<key>` |
| 部件 | `art/parts/<key>/<部件 id>` |
| rig 描述 | `art/rig/<key>`（JSON） |

## 3 PNG / JPG 规格

| 项 | 规格 |
|---|---|
| 颜色 | sRGB，RGBA，透明底，**非预乘** alpha |
| 尺寸 | 等于清单 `size`，像素整数 |
| 压缩 | PNG 过一遍 `pngquant --quality=70-90`；背景导 JPG，质量 82 |
| 边缘 | 外轮廓到画布边至少留 4px（投影、洇边、光晕也算在内），不能被裁 |
| 文字 | 图里的字（按钮字、标题字、数字）画成笔触 / 剪纸 / 缝线路径，不用字体 |
| 体积 | 每个 demo 全部图片加起来 ≤ 2.0 MB（微信主包 4 MB，引擎和代码要占一半） |

## 4 rig 资源：部件 PNG + rig JSON

清单里 `kind: "rig"` 的资源（角色、会动的道具）除了整图，还要交**部件**和**描述文件**，开发用它在引擎里拼出角色、做补间动画。

### 4.1 部件怎么拆

- 部件就是 SVG 里带 `id` 的那一层 `<g>`，名字照清单 `parts`，一个不少。清单里没列、但你觉得需要的部件可以加，在 notes.md 里写明。
- 每个部件单独导出一张 PNG：只画这一层自己的内容（**不含**嵌在它里面的子部件），裁到内容外框再外扩 2px，导出比例和整图相同（1:1）。
- `hidden` 里的部件（闭眼、张嘴、配件……）默认不显示，但也要导出。
- 部件之间的接缝按 style-lab 墨线手绘 README 4.3 的做法处理：会转的部件根部埋进母体 8–15px，转起来不露缝。

### 4.2 rig JSON 格式

```json
{
  "key": "hero_motuan",
  "size": [192, 192],
  "anchor": [96, 170],
  "parts": [
    { "id": "shadow", "parent": null,   "png": "parts/hero_motuan/shadow", "rect": [44, 158, 104, 26], "pivot": [96, 170] },
    { "id": "body",   "parent": null,   "png": "parts/hero_motuan/body",   "rect": [38, 40, 116, 132], "pivot": [96, 168] },
    { "id": "tuft",   "parent": "body", "png": "parts/hero_motuan/tuft",   "rect": [80, 18, 36, 40],   "pivot": [96, 52] },
    { "id": "blink",  "parent": "body", "png": "parts/hero_motuan/blink",  "rect": [62, 92, 70, 16],   "pivot": [96, 100], "hidden": true }
  ],
  "anims": {
    "idle": { "dur": 1600, "loop": true, "tracks": [
      { "part": "body", "prop": "sy", "keys": [[0, 1], [0.5, 0.96], [1, 1]], "ease": "sineInOut" },
      { "part": "tuft", "prop": "rot", "keys": [[0, -4], [0.5, 4], [1, -4]], "ease": "sineInOut" }
    ] },
    "hop": { "dur": 240, "tracks": [
      { "part": "body", "prop": "sy", "keys": [[0, 1], [0.3, 0.85], [0.6, 1.08], [1, 1]], "ease": "quadOut" }
    ] }
  }
}
```

| 字段 | 说明 |
|---|---|
| `parts` | **按绘制顺序排，从后往前**（就是 SVG 里的先后）。父部件自己的图和它的子部件也按这个顺序叠 |
| `parent` | 父部件 id；`null` 表示直接挂在角色根上 |
| `png` | 部件图路径（相对 `art/`，不带扩展名） |
| `rect` | 部件图在整张画布里的位置 `[x, y, 宽, 高]` |
| `pivot` | 旋转 / 缩放中心（画布坐标）。会转的部件放在关节上（肩、髋、耳根、帽沿），不放在几何中心 |
| `hidden` | 默认隐藏 |
| `anims` | 可选。名字照清单 `events`。没有的事件开发用程序动画代替 |
| `tracks[].prop` | `x` `y`：位移（像素，y 朝下）；`rot`：角度（**顺时针为正**，和 CSS 一致）；`sx` `sy`：缩放倍数；`op`：不透明度 0–1；`vis`：显示 0 / 1（瞬间切换，用来眨眼、换嘴） |
| `tracks[].keys` | `[时间, 值]`，时间是 0–1 的归一化比例 |
| `tracks[].ease` | `linear` `sineInOut` `quadIn` `quadOut` `backOut` `step`，缺省 `sineInOut` |

动画只做部件绕 pivot 的位移、旋转、缩放和显隐，**不要**改形状。整只角色在棋盘上的移动（走一格、跳过去、飞出屏幕）由开发做，rig 动画只管原地的身体动作。

### 4.3 开发怎么拼（给美术参考）

每个部件在引擎里是一个“关节”节点，放在自己的 `pivot` 上；部件图挂在关节下面，偏移到 `rect` 的位置。父子关系照 `parent`，同一个父亲下面的东西按 `parts` 的顺序叠。所以：

- `pivot` 写错，转起来会绕错地方；`rect` 写错，图会错位。导出脚本请直接从 SVG 里读（`getBBox` + `<!-- pivot -->` 注释），不要手填。
- 交付前请用整图对照：把所有非隐藏部件按 rect 叠回去，应该和 `png/<key>.png` 一模一样。

## 5 动画事件名

各 demo 的事件名写在清单的 `events` 里，`dur` 是建议时长（毫秒），`loop: true` 表示循环。约定：

- `idle` 一定有，循环，起止姿势相同（接回待机不跳）。
- 一次性事件播完必须回到 `idle` 的第一帧姿势。
- 开发可以按手感改时长（等比缩放 `dur`），美术不用为此改图。
